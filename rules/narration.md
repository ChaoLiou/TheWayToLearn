# 聽力版講稿規則（narration.json）

改這個檔案就是改 `/learn-narrate` 產出的聲音內容。目標：**閉著眼睛通勤時聽也學得會**。

## 結構
以「段」為單位重複這個節奏，順序不可換：

1. **引言（say）**：這一段要解決什麼問題、承接上一段留下的什麼線索（用 analysis 的 `builds_on`）。1–2 句。
2. **導聽（say）**：一句話說明接下來要聽什麼、聽的時候注意什麼。例如「我們先聽作者怎麼形容這個問題，注意他用的比喻」。
3. **原聲（clip）**：播 `segments.json` 的 `clips`。沒有 clip 的段落跳過 2、3。
4. **說明（say）**：用 analysis 的 `reasoning` + `explanation` 改寫成口語，把剛剛聽到的內容接住。可以點出作者沒說清楚的地方。
5. **術語（say，可選）**：該段首次出現的術語，用一句話解釋，唸原文再說中文。
6. **收束（say）**：這一段留下什麼問題給下一段（用 `leads_to`），讓聽的人有預期。

開頭加一段總引言（主題、會學到什麼、大約多長），結尾加總結與三個下一步。

## 口語化（最重要）
講稿是**寫給耳朵**的，不是把 `explanation` 直接搬過來：
- 短句。一句話一個意思。避免破折號、括號、分號。
- 不要唸出「第 3 段」「見上圖」「如表所示」這類只有看得到畫面才懂的指涉。
- 數字與符號寫成會唸的樣子：`3x` → 三倍、`≥ 2` → 兩個以上、`S3` → S 三。
- 英文術語直接唸原文，第一次出現時補一句中文解釋。
- 每個 `say` block 控制在 60 個字以內；長內容拆成多個 block。

## 原聲片段（clip）

取自 `segments.json` 的 `clips`。**預設放整段**：聽的人需要完整的來龍去脈，太短會不知道在講什麼。

| 段落長度 | 怎麼取 |
|---|---|
| ≤ 150 秒 | **整段**：`start` = 段落 start，`end` = 段落 end |
| > 150 秒 | 取其中最核心的 60–120 秒；捨掉重複、離題、口水的部分 |
| 這段沒有值得聽原音的（純過場、純清單） | 不給 clip |

- 起訖秒數不必精算：`narrate.py` 會自動對齊到 transcript 的句子邊界，不會從半句開始或斷在半句。
- 講稿不要重複原聲已經說完的內容，要做「接住」與「補充」。
- 導聽那句要給明確的收聽重點（「注意他用的比喻」），因為片段變長了。

## 語言與語音
- 講稿語言用該站 `meta.json` 的 `output_lang`。
- `voice` 預設：`zh-TW` → `zh-TW-HsiaoChenNeural`，`en` → `en-US-AriaNeural`。使用者指定就照他的。
- `rate` 預設 `+0%`；使用者嫌慢可設 `+15%`。
