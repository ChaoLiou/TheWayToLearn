# 消化工作單規則（/learn-digest）

改這個檔案就是改 `/learn-digest` 產 `digest.json` 的行為。目的：讀完（消費期）之後，把這一站的每一筆資訊標上 **PACER** 類別，並寫下該類專屬的消化動作，讓使用者去做——而不是再讀一次。硬規則由 `scripts/validate.py check_digest` 執行。

## 為什麼要分類

每類資訊有專屬的消化流程；用錯流程會更難記、更快忘。消費期邊讀邊辨識類別，消化期用對的流程處理。兩期必須平衡：沒時間消化就少讀，不是多讀。

## 讀什麼

- `analysis.json`：每段的 `reasoning`、`explanation`、`terms`——工作單的原料
- `_overview.json`：`takeaways`——判斷哪些才是這站真正要消化的
- 已有 `digest.json` 時：只在 `--force` 時覆寫（使用者的 `digest.state.json` 靠 `id` 對，重產會讓狀態失效）

## 分類的單位是「一筆資訊」，不是一段、不是一支影片

一段通常拆出 2–5 筆，一站合計 10–40 筆（上限 60）。每筆一個 `kind`，寫之前先問自己：

| kind | 問句 | 消化動作 | 必填欄位 |
|---|---|---|---|
| **P** procedural | 這是在教「怎麼做」嗎？ | **練習**：盡早在真實情境用 | `procedure`（步驟）、`practice_task` |
| **A** analogous | 這跟我已知的什麼很像？ | **批判**：哪裡像、哪裡不像、何時失效 | `new`、`known` |
| **C** conceptual | 這是在講「是什麼／為什麼」嗎？ | **畫地圖**：自己把概念連成網路 | `concept`、`relations` |
| **E** evidence | 這是支持某個概念的細節／數字／案例嗎？ | **存＋演練**：當下存，之後想「它證明了什麼、怎麼用」 | `detail`、`supports`、`rehearse_q` |
| **R** reference | 瑣碎、具體、不改變理解、但之後可能要查？ | **存＋回想**：flashcard 間隔重複 | `q`、`a` |

分不清時的判準：
- 「這改變我對概念的理解嗎？」是 → C（或 E，如果它是例子）；否 → R
- 「它是拿來說明一個概念的嗎？」是 → E，`supports` 指向那個 C
- 「它有『第一步、第二步』的形狀嗎？」是 → P
- A 常常同時是 P 或 C 的子集：影片用類比解釋一個步驟或概念時，另外開一筆 A，不要塞進那筆 P／C

## 每類怎麼寫

- **P**：`procedure` 1–8 步，照著就能做；`practice_task` 是**今天**就能在使用者自己的專案／生活裡做的一件事，≤ 30 分鐘，寫成一句指令（「拿你正在讀的下一篇文章，邊讀邊畫 5 個節點的地圖」），不是「試試看」。
- **A**：`new` 是影片裡的新東西，`known` 是它被比成的舊東西（使用者既有知識，或影片內先出現的概念）。`critique_key` 選填：AI 先寫一版哪裡像／不像／失效，當答案卷，頁面預設不顯示。
- **C**：`concept` 用英文原文，同站內唯一（同一概念只開一筆，多段提到就選最核心那段當 `seg_id`）。`relations` 是答案卷：至少一條，`to` 必須是同站另一筆 C 的 `concept` 或 `analysis.json` 的 `term`，`rel` ≤ 12 字。
- **E**：`detail` 保留數字、名字、年份等具體資訊；`supports` 必須是同站某筆 C 的 `concept`；`rehearse_q` 是演練時問自己的問題，不是「這是什麼」而是「它證明了什麼／你會怎麼用它」。
- **R**：`q` 一句問句、`a` 短到一眼看完。只放**之後真的可能要查**的東西；影片開場白、頻道名、作者生平不算。**人名、公司名、募資額、日期、「影片舉了哪幾個例子」「有哪三種質疑」這種清單題也不算**——使用者實測一律刪掉。R 該是「用的時候會需要的事實」：某個縮寫的全名、某個行為是不是確定性的、某個保證的實際範圍。判斷法：這張卡答錯，會不會讓他做錯什麼？不會就別出。

## 挑什麼、不挑什麼

- 只留**看完之後才知道**的東西；常識、標題本身不算。
- 每筆一定有 `seg_id`：找不到出處的不要寫。
- 一筆只講一件事。`text` 一句話（≤ 80 字），三個月後看到還懂。
- 寧可少而準：R 卡超過 15 張通常代表把 E 或 C 誤判成 R。
- **C 一站最多 10 筆**（validator `MAX_C` 擋）：地圖超過 10 個節點就畫不動了。術語密集的影片先挑「拿掉它整支影片就講不通」的概念當 C，其餘術語降成 R（q = 「X 是什麼？」）或併進相關 C 的 `text`；被 `relations[].to` 指到但沒開 C 的名字，只要是 analysis term 就合法。

## 語言

`text`、`practice_task`、`rehearse_q`、`q`／`a` 等內文用該站 `meta.json` 的 `output_lang`；`concept`、`terms`、`relations[].to` 永遠英文原文。

## 產出後

1. `scripts/validate.py digest <站>/digest.json`（schema、每類必填、`seg_id` 存在、`relations[].to` / `supports` 指向存在的 concept）
2. `scripts/digest.py` 重產 `workspace/digest.html`（第 2 階段做完才有）
