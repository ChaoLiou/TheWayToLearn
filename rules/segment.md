# 切段規則

改這個檔案就是改 /learn-segment 的行為。

## 段落
- 一段 = 一個可獨立陳述的推理步驟或主題轉折，不是固定時間長度。
- 段數建議 3–30。太碎會讓線性推進變成流水帳。
- 每段必有 `title`（≤ 20 字）、`summary`（該段作者說了什麼，2–4 句）。

## 截圖時間點（shots）

先看 `shots_mode`（來自使用者的 `--shots`，預設 `auto`）：

| shots_mode | 怎麼做 |
|---|---|
| `none` | **完全不截圖**：每段 `shots` 都是空陣列，`vision` 一律 false。步驟 4 會自動跳過、不下載影片。用於「畫面沒有資訊、重點都在講話」的影片。 |
| `auto`（預設） | 只挑「看了才懂」的瞬間：圖表、程式碼、白板、示意圖、對照表。純講話段落 0 張；有視覺依賴的段落 1–3 張。**整支影片都沒有值得截的畫面時，就全部 0 張並把 `shots_mode` 改寫成 `none`**，並在 `vision_reason` 說明理由。 |
| `many` | 投影片型影片：每段至少 1 張，最多 3 張。 |

- 每個 shot 寫 `why`：這張圖在推理裡扮演什麼角色。寫不出 `why` 就不該截。
- 同一張投影片不要重複截（作者停在同一畫面講很久時只取一張）。

## vision 判斷（input 為 auto 時；`shots_mode: none` 時一律 false）
- transcript 中出現「這張圖」「你看這裡」「這段 code」「如圖」等指示語 ≥ 3 次 → `vision: true`
- 否則 `vision: false`
- 把理由寫進 `vision_reason`。
